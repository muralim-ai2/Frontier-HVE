Build a web-based front-end for "Pawstagram", a social photo app for dogs. It works like Instagram, but every account belongs to a dog, run by its owner. Visually and interaction-wise, it should feel like a real, shipping product from a top-tier consumer app company. Someone should be able to mistake a screenshot of it for the real thing. Treat this as if it were going to be shown in a design review with a world-class product design team in the room. TIME BUDGET You have about xx minutes. Don't build the whole app. Build three screens to a finished, shippable standard: Home Feed, Dog Profile and Pack Hive. Every other destination should exist as a navigable placeholder so the app feels complete to click through. Prioritize depth and polish on the built screens over breadth. TECH CONSTRAINTS - Deliver a single self-contained web app (one HTML file with embedded CSS and JS, or a minimal React/Vite project; your choice). - No backend. Use realistic hard-coded mock data. - Use real dog photos from a public placeholder source (for example https://placedog.net or https://images.dog.ceo) for avatars and post media. - Render it inside a mobile viewport frame (around 390px wide) centered on a desktop browser. It should also work when opened directly on a phone. - No UI component libraries. Hand-build every element. SCREEN 1: HOME FEED (fully built) 1. Top app bar - A "Pawstagram" wordmark on the left. - Two icons on the right: notifications (heart) and messages (paper plane). Show an unread badge on messages. - The bar stays visible while the feed scrolls. 2. Stories tray - A horizontally scrollable row of at least 10 circular dog avatars with names below them. - The first item is "Your story", with an add indicator. - Unseen and seen stories look visibly different from each other. - Include some very long dog names (e.g., "sir_barkington_the_third", "princess.waffles.mcfluff") alongside short ones (e.g., "rex", "bo"). - Tapping a story opens a full-screen story viewer with a progress bar, the dog's avatar and name, a timestamp, a close button, and tap-left/tap-right navigation between stories. It auto-advances after about 5 seconds. 3. Feed posts (at least 6, with variety) Each post includes: - A header with avatar, dog name, an optional verified badge, an optional breed or location line, and an overflow (•••) menu. - Media. Include at least one square post, one portrait post, and one multi-image carousel with swipe/arrow navigation and position dots. - An action row: like (a paw or heart), comment, share and save. Like and save toggle state. - Double-tapping the media likes the post and plays a brief animation over the image. - A like count that updates live, with numbers formatted naturally (e.g., 1,204 likes; 12.4K; 1.2M). - A caption led by the dog's name, written in the dog's voice, with inline #hashtags and @mentions. Long captions truncate with a "more" toggle. - A "View all N comments" link, one or two preview comments, and a relative timestamp. - Mix the content: beach days, zoomies, birthday cakes, grooming glow-ups, sleepy puppies and agility wins. 4. "Good boys you may know" interstitial - Somewhere in the middle of the feed, add a horizontally scrolling row of suggested dog accounts. - Each card shows an avatar, name, breed, a reason line (e.g., "Sniffed by luna.the.husky + 3 more"), a Follow button that toggles to Following, and a dismiss X. SCREEN 2: DOG PROFILE (fully built) 1. A header bar with the handle, a dropdown chevron, and create/menu icons. 2. A profile summary: - A large avatar with a story ring. - Posts, followers and following counts. Use values of very different lengths, e.g., 87 / 1.4M / 312. - The dog's display name, a breed tag pill, an age and a "Good Boy since 2019" line. - A multi-line bio with emoji and a link, plus a "Followed by…" line with stacked mini-avatars. 3. Buttons: Edit profile, Share profile, and a small add icon button. 4. A highlights row of at least 5 circular covers (e.g., Park, Vet 😬, Treats, Bath Day, Besties) plus a "New" item. 5. A tab switcher for Grid, Pack and Tagged with an active indicator. - Grid shows the posts grid below. - Pack opens Screen 3. - Tagged shows a designed empty state with an icon, a heading and one line of supporting text. 6. A posts grid: - At least 20 tiles in a three-column layout. - The first tile is a pinned "featured" post spanning 2 columns × 2 rows. The remaining tiles flow around it with no holes. - Some tiles show small overlay indicators for carousel or video content, and the pinned tile shows a pin icon. - On hover/press, show the like and comment counts over the tile. - Tapping a tile opens a post detail view that reuses the feed post component, with a back button. SCREEN 3: PACK HIVE (fully built) This screen shows the dog's social circle as a honeycomb flower. 1. Layout - At the center is one large hexagon containing the profile dog's photo, name and breed. - Six hexagon cards surround it. Each card sits against one side of the center hexagon, so together they form a sunflower or honeycomb bloom. - The shape must stay intact and centered within the 390px mobile viewport, and it must not overflow or clip. 2. Card content Each of the six cards is a "pack member" showing a photo, name, relationship label and a stat. The content deliberately varies in size: - "bo" · Best Friend · 3 playdates - "sir_barkington_the_third" · Rival · 1,284 sticks stolen - "luna.the.husky" · Sister · 14.2K treats shared - "pickles" · Neighbor · 7 fence chats - "duchess_of_dogwood_lane" · Crush 💕 · 52 tail wags - "max" · Walk Buddy · 2.3M steps 3. Interaction - Tapping a card expands it into a detail sheet (bottom sheet or modal) with a larger photo, a short bio, a "Sniff profile" button and a close control. - Tapping the center hexagon returns to the profile. - On first load, the six cards animate outward from the center in sequence. 4. Pack summary strip - Below the honeycomb, show three summary stats: Pack size, Total playdates and Longest friendship (e.g., "4 yrs 2 mo"). - The labels and values should differ greatly in length. PERSISTENT BOTTOM NAVIGATION - Five tabs: Home, Search, Create, Reels and Profile. The Profile tab uses the dog's own avatar instead of an icon. - The active tab shows a clear selected state. - Home and Profile route to the built screens. - Search, Create and Reels route to placeholder screens. Each placeholder has the correct top bar title and a thoughtfully designed, dog-themed empty state (icon, title, short description), so the app never feels broken. - The heart and messages icons also route to placeholder screens with a back button. INTERACTION AND FEEL - Every tappable element gives press/hover feedback. - Transitions between screens, sheets and overlays feel smooth and intentional. - Use a light theme only. - Icons are crisp, consistent with each other and recognizable. Use inline SVG; no emoji as icons (emoji in user-written text such as bios and captions is fine). - Mock data reads like real dog accounts. No lorem ipsum anywhere. QUALITY BAR This will be compared side by side against the real Instagram app and against other submissions. A reviewer should be able to screenshot any built screen and have it pass as a real app capture. Use your own professional judgment wherever this spec is silent. Don't ask clarifying questions; make the call a senior product designer and front-end engineer would make. DELIVERABLE Working code that runs with no setup beyond opening the file (or `npm install && npm run dev`). Also include a short README listing what is fully built and what is a placeholder.
